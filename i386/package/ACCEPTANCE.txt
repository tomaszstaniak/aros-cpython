C. THE TWO FIXES AGAINST THE FIRST i386 BUILD
---------------------------------------------
The first i386 build (50aac094..., the binary of the first Lib/test pass)
was accepted the same way and failed:
FAIL  wheel-test.py (first build): pip installed the wheel ("Successfully
      installed") and then ended with OSError errno 0 from
      del os.environ[...]. Cause: unsetenv() of ABIv0 has no return
      statement (L15). This interpreter: PASS 6 of 6.
FAIL  threadident.py (first build): 349 of 400 threads in the "one after
      another" case saw an ident different from the creator's; threads11.py
      printed "Exception ignored ... KeyError" from threading._delete().
      Cause: pthread_self() of ABIv0 can return another thread's number
      (L14). This interpreter: PASS 8 of 8, no background exception.
The system bugs are still present on the tested system (checked in both
runs with C programs from i386/tests/c: tidprobe 108 of 400 threads
mismatched; unsetenvprobe -1 with errno 0 after a successful delete); the
interpreter no longer depends on them.
The interpreter differs from the first build only in Modules/posixmodule.o
and Python/thread.o (all other object files are identical after
--strip-debug).

KNOWN LIMITS
------------
L1  (x86_64 build; NOT CHECKED on i386) Ctrl-C and Break do not interrupt
    a script.
L2  Sockets only in the main thread. In any other thread, name lookup
    fails (gaierror "getaddrinfo failed") and socket() fails with OSError
    errno 0. Effect: network servers and clients in worker threads do not
    work.
L3  No processes: subprocess, os.popen and multiprocessing raise OSError
    "aros does not support processes". os.system works.
L4  Missing modules: _ctypes/ctypes, mmap, _curses/curses, readline, _dbm,
    _gdbm, _tkinter, termios (and tty, pty), resource, syslog,
    _posixsubprocess, _posixshmem, _multiprocessing, _uuid, _zstd, and
    sqlite3/_sqlite3. Importing them fails.
L5  pip installs pure-Python wheels only (sdists need subprocess). The
    bundled pip is changed so that it loads without mmap.
L11 Startup needs AROSTCP running (bsdsocket.library is opened at start).
L14 (fixed in this interpreter; system bug) pthread_self() of ABIv0 can
    return the number of another thread: GetThreadId() in
    compiler/pthread/pthread.c at ABIv0_20250313-1 takes the first slot
    with the caller's task pointer, including a finished, unjoined thread
    whose task structure had the same address. ABIv11 fixed the lookup.
    This interpreter takes each thread's number from pthread_create()
    (patch 0025).
L15 (fixed in this interpreter; system bug) unsetenv() of ABIv0 has no
    return statement: it returns -1 with errno 0 after a successful delete.
    This interpreter ignores its result, as CPython does on systems whose
    unsetenv() returns nothing (config.site: ac_cv_broken_unsetenv=yes).
    Effect that remains: os.unsetenv() cannot report errors on ABIv0.
L16 Several ABIv0 C library calls fail without setting errno, so Python
    reports OSError errno 0 ("Error"): seen in Lib/test for
    fcntl(F_SETFL, O_NONBLOCK), os.fstat() on descriptor 1 in a test
    harness, os.get_terminal_size() and os.open() near the descriptor
    limit. The operation fails either way; only the error code is missing.
